This sprint turns the program specification of Sønderborg's digital media platform into a design: requirements, a verb-noun analysis, CRC cards and a UML class diagram.

\textbf{Scope.} The design covers the core of the specification: seven media types, three user categories, borrowing and rating, collection and user management, and a console interface that asks for the user's role on startup. Authentication, returning items, sorting and file persistence are left out.

\section{UML class diagram}

The diagram is split in two figures. Figure~\ref{fig:media} shows the media model and Figure~\ref{fig:system} shows users, library and console interface. The main design decisions are:

\begin{itemize}
  \item \textbf{Abstract base class for media.} \texttt{Media} holds id, title, borrowers, ratings and download. The seven types are subclasses, so a new type is just a new subclass (NFR1).
  \item \textbf{Two small interfaces.} \texttt{IPlayable} and \texttt{ICompletable} cover the verbs shared by only some types: \texttt{Podcast} and \texttt{VideoGame} are both, \texttt{Song} is only playable.
  \item \textbf{Rating rule in the domain.} \texttt{Media.Rate()} throws an exception if the user has not borrowed the item (FR4, NFR2).
  \item \textbf{User hierarchy.} \texttt{Admin} extends \texttt{Employee}, since an admin has all rights of an employee (FR9).
  \item \textbf{Separate presentation.} \texttt{ConsoleUI} depends on the domain classes, never the other way around (NFR3).
\end{itemize}

Properties, constructors and trivial helpers are left out. Abstract classes and operations are written in italics.
